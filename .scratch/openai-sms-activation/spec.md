# OpenAI 短信激活授权网站规格

**Status:** `ready-for-agent`

## Problem Statement

管理员目前需要通过聊天软件向指定接收者提供临时 OpenAI 验证号码，但手工号码获取、换号、等待短信、取消和核对 HeroSMS 结果无法形成稳定流程。管理员也不可能一直在线替接收者操作，而接收者不应接触 HeroSMS、价格、余额和退款确认等内部信息。

系统需要让管理员通过一次私发授权，把最多三个候选地区的号码获取资格交给接收者，同时保证任意时刻只有一个未结束的供应商激活，避免重复号码、错误扣费、状态竞争和敏感数据长期保存。系统只能证明短信送达，不能声称 OpenAI 验证成功。

## Solution

构建一个封闭、简体中文、移动优先的网站。管理员使用密码进入隐藏入口，配置 OpenAI 默认三个候选地区，并为一个接收者标识生成 24 小时授权链接。接收者打开链接后无需填写信息，明确点击获取号码才绑定浏览器并触发 HeroSMS 号码获取。

系统按剩余候选地区的实时价格排序获取号码。号码获取满两分钟且未收到短信时，接收者可以确认换号；HeroSMS 明确取消旧激活后，系统自动获取下一个号码。一条激活授权最多成功获取三个号码，每个候选地区最多一次。短信通过 Webhook 接收，轮询兜底；短信送达立即终止换号资格，结构化验证码可直接展示，否则由管理员在有效窗口内查看短信正文并协助接收者。

激活授权和供应商激活采用独立生命周期。授权创建满 24 小时后，接收者访问绝对终止并删除 token 哈希；截止时已有供应商激活继续由后台收尾。完整号码、验证码和短信正文仅在当前流程需要时保存，结束后立即删除。

## User Stories

### 管理员访问与设置

1. 作为管理员，我希望通过自定义后台路径访问登录页，从而减少常见后台路径的自动扫描。
2. 作为管理员，我希望只使用密码登录，从而保持单人管理流程简单。
3. 作为管理员，我希望新浏览器登录后旧浏览器会话自动失效，从而保证只有一个活跃管理员会话。
4. 作为管理员，我希望登录会话最长保留 30 天，从而不必频繁重新登录。
5. 作为管理员，我希望在后台看到 HeroSMS 连接状态和余额，从而在生成授权前发现明显配置问题。
6. 作为管理员，我希望设置恰好三个互不重复的默认候选地区，从而不必每次生成授权时重复选择。
7. 作为管理员，我希望设置候选地区时看到 OpenAI 当前价格和库存，从而只保存可用配置。
8. 作为管理员，我希望修改默认候选地区只影响新授权，从而不改变已经发出的授权链接。
9. 作为管理员，我希望已有授权的候选地区不可编辑，从而保持授权内容和历史一致。

### 创建与发送激活授权

10. 作为管理员，我希望只填写接收者标识和可选内部备注即可生成授权链接，从而快速完成私发流程。
11. 作为管理员，我希望接收者标识为必填，从而能够区分不同授权记录。
12. 作为管理员，我希望内部备注只在后台显示，从而记录必要背景而不向接收者泄露。
13. 作为管理员，我希望同一接收者标识同一时间最多存在一条未结束授权，从而避免重复生成导致多次号码获取。
14. 作为管理员，我希望生成前验证 HeroSMS 密钥、余额、三个候选地区的价格和库存，从而避免发送明显不可用的链接。
15. 作为管理员，我希望任一候选地区无库存时无法生成授权，从而不把已知不可用的配置发给接收者。
16. 作为管理员，我希望余额至少覆盖三个候选地区当前最高价格时才可生成授权，从而确认当前时点具备获取任一候选地区单个号码的余额。
17. 作为管理员，我希望确认框汇总接收者标识、三个候选地区、价格和库存，从而在生成前发现错误。
18. 作为管理员，我希望确认后授权立即生效 24 小时，从而无需草稿或额外启用步骤。
19. 作为管理员，我希望完整授权链接只在生成成功时显示一次，从而降低数据库或后台泄露有效 bearer URL 的风险。
20. 作为管理员，我希望通过复制按钮取得授权链接，从而通过既有聊天软件私发给接收者。
21. 作为管理员，我希望丢失完整链接时撤销并重新生成，而不是从数据库恢复，从而保持 token 单向存储。

### 接收者领取

22. 作为接收者，我希望打开授权链接时无需注册或填写信息，从而直接进入号码获取流程。
23. 作为接收者，我希望初始页面只显示 OpenAI、授权剩余时间和获取号码按钮，从而只看到当前需要的信息。
24. 作为接收者，我希望仅打开页面或被聊天软件预览时不会获取号码，从而避免爬虫或预览消耗授权。
25. 作为接收者，我希望点击获取号码后才绑定当前浏览器并开始号码获取，从而让操作由真实意图触发。
26. 作为接收者，我希望号码获取期间看到简短等待状态，从而不知道也无需理解号码获取队列和 HeroSMS 状态。
27. 作为接收者，我希望号码成功取得后看到当前地区和完整国际号码，从而能够在 OpenAI 中使用。
28. 作为接收者，我希望号码以易读国际格式显示，复制时得到带加号且无空格的 E.164 号码，从而避免粘贴格式错误。
29. 作为接收者，我希望看到授权剩余时间、号码有效时间和可换号倒计时，从而知道每个期限的含义。
30. 作为接收者，我希望看到剩余可用号码次数，从而理解换号或激活超时后再次获取的后果。
31. 作为接收者，我不希望看到候选地区列表、价格、库存、HeroSMS、号码获取过程、余额、退款确认或激活 ID，从而保持页面简单。

### 地区排序与号码获取

32. 作为接收者，我希望系统在每次号码获取前按剩余候选地区实时价格排序，从而优先取得当前最低价地区的号码。
33. 作为接收者，我希望明确无库存的地区被自动跳过，从而继续尝试其他候选地区。
34. 作为管理员，我希望无库存不消耗候选地区或获取额度，从而让该地区恢复库存后仍可使用。
35. 作为管理员，我希望只有 HeroSMS 返回激活 ID 和号码才消耗一次获取额度，从而不把失败请求算作号码获取。
36. 作为接收者，我希望三个候选地区都无库存时看到“当前暂无可用号码，请联系发送者”，从而知道下一步动作。
37. 作为接收者，我希望管理员处理后能够在原绑定浏览器重新尝试，从而无需因临时错误立即更换授权链接。
38. 作为管理员，我希望余额不足、密钥无效、账号受限或供应商错误不会自动尝试其他地区，从而避免无意义重复请求。
39. 作为接收者，我希望内部错误统一显示为“暂时无法获取号码，请联系发送者”，从而不泄露供应商账户信息。
40. 作为管理员，我希望号码获取结果不确定时先对账而不是盲目重试，从而避免重复激活和双重扣费。
41. 作为管理员，我希望所有号码获取请求全局串行，从而使结果不确定时能够唯一归属供应商激活。

### 换号与超时

42. 作为接收者，我希望号码获取满两分钟且未收到短信后出现换号操作，从而不必固定等待 20 分钟。
43. 作为接收者，我希望换号前看到“更换后当前号码将不能继续使用”的二次确认，从而避免误操作。
44. 作为接收者，我希望“继续等待”是确认框默认操作，从而降低意外换号概率。
45. 作为接收者，我希望确认换号后只看到“正在更换号码”，从而不接触供应商取消和退款对账细节。
46. 作为接收者，我希望 HeroSMS 明确取消当前激活后系统自动获取下一个号码，从而不依赖管理员在线。
47. 作为管理员，我希望取消结果不明确时系统停止获取新号码并对账，从而保证每条授权最多一个未结束激活。
48. 作为接收者，我希望换号确认期间短信先到时停止换号并展示短信结果，从而不会丢失已到达的验证码。
49. 作为接收者，我希望取消先成功时旧号码失效并继续换号，从而得到确定且唯一的当前号码。
50. 作为接收者，我希望当前激活超时后系统不自动获取新号码，从而不会在我离开页面后产生无人使用的激活。
51. 作为接收者，我希望激活超时后在授权仍有效且有剩余获取额度时可以点击获取下一个号码，从而继续完成流程。
52. 作为接收者，我希望三个候选地区都已成功获取过后不能继续换号，从而遵守获取额度。

### 短信与验证码

53. 作为接收者，我希望短信到达后立即停止换号流程，从而不会丢弃已经计费的短信结果。
54. 作为接收者，我希望结构化验证码到达后立即看到验证码和复制按钮，从而尽快在 OpenAI 中使用。
55. 作为接收者，我希望 `finishActivation` 暂时失败时仍能看到验证码，从而不被后台对账阻塞。
56. 作为接收者，我希望页面关闭后后台仍继续接收短信，从而不必一直保持页面打开。
57. 作为接收者，我希望在授权到期前通过已绑定浏览器重新打开链接仍能查看当前结果，从而恢复被关闭的页面。
58. 作为接收者，我希望短信已到但没有结构化验证码时看到“短信已收到，暂时无法显示验证码，请联系发送者”，从而能够通过原聊天渠道求助。
59. 作为接收者，我希望系统之后取得结构化验证码时页面自动改为显示验证码，从而无需手动刷新状态。
60. 作为管理员，我希望结构化验证码缺失时在当前有效窗口内查看短信正文，从而人工协助接收者。
61. 作为管理员，我希望短信送达后系统不再允许换号或期待退款确认，从而符合 HeroSMS 的实际计费规则。
62. 作为管理员，我希望系统只记录“短信送达”而不记录“OpenAI 验证成功”，从而不声称无法观测的第三方结果。

### 授权期限、绑定与撤销

63. 作为接收者，我希望页面显示距离授权创建满 24 小时的剩余时间，从而知道绝对访问期限。
64. 作为接收者，我希望 24 小时截止时原链接立即失效并返回 404，从而执行明确的绝对期限。
65. 作为管理员，我希望授权到期时仍存在的供应商激活继续由后台收尾，从而不忽略已经发生的供应商请求。
66. 作为管理员，我希望截止后才确认买到的号码不交付给接收者并在允许时自动取消，从而减少无用成本。
67. 作为管理员，我希望截止时已有激活之后收到短信时可以在后台查看结果，从而通过聊天软件协助接收者。
68. 作为接收者，我希望换浏览器、清除 Cookie 或关闭无痕会话后不能用原链接重新绑定，从而防止授权被转移。
69. 作为管理员，我希望绑定丢失时可以查看当前有效号码或验证码并通过聊天协助，而不是重置设备绑定。
70. 作为管理员，我希望撤销待领取授权时立即使链接不可用，从而阻止尚未开始的流程。
71. 作为管理员，我希望撤销等待短信的授权时立即终止接收者访问，并在 HeroSMS 允许时取消当前激活，从而停止后续使用。
72. 作为管理员，我希望撤销结果不明确的授权时先完成对账再取消实际激活，从而避免遗漏号码。
73. 作为管理员，我希望短信已送达后撤销只终止接收者访问，从而不伪造不可执行的供应商取消或退款确认。
74. 作为管理员，我希望已结束或已到期的激活授权不再显示撤销操作，从而避免无意义的状态变更。
75. 作为接收者，我希望真实但暂时不可用的授权在 24 小时内统一显示“此链接不可用，请联系发送者”，从而不泄露失效原因。
76. 作为接收者，我希望随机错误的授权地址和 24 小时后的旧地址返回标准 404，从而不暴露历史 token 是否存在。

### 管理员状态与成本

77. 作为管理员，我希望首页看到最近授权和当前状态，从而快速发现需要处理的记录。
78. 作为管理员，我希望授权状态和当前激活状态分别展示，从而同时看见“授权已到期”和“当前激活等待短信”等真实情况。
79. 作为管理员，我希望详情页展示三个候选地区、获取次数和每次供应商激活，从而理解完整生命周期。
80. 作为管理员，我希望撤销确认框显示接收者标识、当前状态、当前地区和撤销后动作，从而避免误操作。
81. 作为管理员，我希望后台分别显示累计激活费用、已确认退款和净成本，从而核对 HeroSMS 余额。
82. 作为管理员，我希望供应商取消确认后可以继续换号而不等待退款对账，从而不阻塞接收者流程。
83. 作为管理员，我希望尚未取得退款确认时不提前减少净成本，从而避免错误财务展示。
84. 作为管理员，我希望非敏感历史长期保留，从而核对激活 ID、费用、退款确认和状态时间。
85. 作为管理员，我希望系统不提供历史删除、批量导出或敏感数据批量查看，从而减少误删和泄露风险。

### 敏感数据

86. 作为接收者，我希望完整号码、验证码和短信正文不进入日志，从而降低凭证泄露风险。
87. 作为管理员，我希望列表页不显示完整号码或验证码，从而避免日常浏览暴露敏感数据。
88. 作为管理员，我希望详情页只在当前流程需要时显示完整号码、验证码或异常短信正文，从而提供必要协助。
89. 作为管理员，我希望供应商取消、号码有效窗口结束、激活超时收尾或供应商对账完成后立即删除敏感交付数据，从而不长期保存无业务价值的数据。
90. 作为管理员，我希望数据库长期只保留接收者标识、候选地区、激活 ID、费用、状态和时间，从而兼顾对账与最小数据保留。

## Implementation Decisions

### 应用形态

- 使用一个 TypeScript Node.js 单体应用交付管理员页面、接收者页面、HTTP 路由、HeroSMS Webhook 和持久后台任务。
- 使用 PostgreSQL 保存激活授权、候选地区、供应商激活、费用、退款确认、会话和持久任务状态。
- 使用 Docker Compose 部署到单台 Linux VPS，通过反向代理提供 HTTPS。
- 第一版仅支持简体中文；管理员页面适配桌面，接收者页面移动优先并兼容聊天软件内置浏览器。
- 根域名、常见后台路径和不存在的授权地址返回 404，不提供公开落地页。

### 深模块与接缝

- 激活授权生命周期模块是业务规则的唯一实现位置，统一接收管理员命令、接收者命令、HeroSMS 事件和时间事件。
- 生命周期模块隐藏授权状态、激活状态、获取额度、候选地区消耗、竞争处理、敏感数据清理和持久任务调度。
- 授权状态固定为：待领取、进行中、短信已送达、额度已用尽、已撤销、已到期。
- 当前激活状态固定为：获取结果确认中、等待短信、取消确认中、已取消、短信已送达、完成确认中、已完成、已超时、结果待人工对账。
- 当前激活的明确终态是已取消、已完成和已超时；结果待人工对账不是终态。
- 已取消仅在授权仍有效、存在获取额度且换号流程要求后继激活时允许自动获取；已超时仅在相同前提下由接收者再次点击获取；已完成绝不允许后继激活。
- HTTP 路由、页面处理器、Webhook 入口和任务循环不得复制生命周期判断。
- HeroSMS 是真实外部依赖，在其接缝定义窄接口；生产使用 HTTP adapter，测试使用脚本化 adapter。
- PostgreSQL 直接作为生命周期模块的持久实现和事务边界，不增加只做透传的仓储接口。
- 时钟在内部接缝注入生产与测试 adapter，以便精确验证 2 分钟、20 分钟和 24 小时行为。

### 授权与浏览器访问

- 授权 token 使用至少 256 位密码学安全随机数并以 Base64URL 编码。
- 数据库只保存 token 哈希；完整授权链接仅在创建响应中返回一次。
- 授权链接采用 `/a/<token>` 形态，初始 GET 不绑定浏览器、不获取号码。
- 首次明确获取号码时消费 token 的领取能力并下发 `HttpOnly`、`Secure`、合适 `SameSite` 的短期浏览器会话 Cookie。
- 原 token 配合同一浏览器会话可在绝对期限内定位当前页面；缺少或不匹配浏览器会话时不重新绑定。
- 授权创建满 24 小时时撤销接收者会话并删除 token 哈希；此后原 URL 返回 404。
- 页面和响应设置禁止索引及严格 Referrer Policy，不加载会把授权 URL 发送给第三方的资源或分析脚本。
- 应用和反向代理日志过滤完整 token、Cookie、后台秘密路径、号码、验证码和短信正文。

### 管理员认证

- 只支持一个管理员，不提供注册、多管理员、角色或网页找回密码。
- 后台入口路径由服务器 `.env` 配置，允许 6 到 12 位英文字母和数字，并拒绝常见后台名称。
- 管理员密码以明文部署 Secret 形式保存在不提交 Git、权限为 `600` 的 `.env` 中；应用和日志不得输出它。
- 登录失败按来源和管理员身份限速，响应不泄露账号是否存在。
- 只允许一个活跃管理员会话；新登录、密码配置变化或容器重新初始化时撤销旧会话。
- 管理员会话设置 30 天绝对期限，不设置闲置超时。
- 后台所有 HTTP 路由和命令独立验证管理员会话，隐藏路径不作为认证手段。

### 默认候选地区与生成预检

- 系统配置一个 OpenAI 服务代码；界面只显示 OpenAI，服务代码不凭文档猜测，应由部署配置或受控供应商数据确认。
- 全局默认候选地区必须恰好为三个互不重复的 HeroSMS 国家或地区 ID。
- 修改默认候选地区只影响之后创建的激活授权。
- 生成授权时复制当前默认候选地区，不允许之后原地修改授权配置。
- 生成前调用 HeroSMS 余额和报价能力，验证密钥、连接、三个地区库存及当前余额。
- 任一地区库存为零、查询失败或余额低于三个地区当前最高价格时阻止生成。
- 同一标准化接收者标识只能有一条未结束激活授权；匹配去除首尾空格并忽略大小写，但不做模糊匹配。
- 不设置价格上限；号码获取以 HeroSMS 实际成交价格和货币为准。

### 号码获取与全局串行

- 接收者号码获取时不额外执行余额或账户预检；只查询剩余候选地区的实时报价和库存用于排序，然后直接获取。
- 对当前有库存的剩余候选地区按实时价格升序尝试。
- `NO_NUMBERS` 允许继续下一个地区；余额、认证、账号限制、参数、限流和供应商错误立即停止。
- 号码获取请求必须全局串行，并通过 PostgreSQL 持久协调，应用重启后不能丢失队列归属。
- 调用 HeroSMS 前再次检查授权绝对期限、获取额度、当前激活和授权状态。
- 只有取得激活 ID 和号码后才创建供应商激活并消耗候选地区和获取额度。
- `NO_NUMBERS`、余额不足、认证失败、账号限制、参数错误、限流和供应商错误只要未产生供应商激活，均不消耗候选地区或获取额度。
- 超时、断网或无法解析的响应进入获取结果确认中；先查询活动激活与历史，不能自动重试或换地区。
- 自动对账无法唯一归属时进入结果待人工对账，并暂停后续号码获取。
- HeroSMS 账户和 API 密钥专供本应用，不允许站外人工或其他程序执行号码获取。

### 激活、换号与时间

- 一个激活授权最多关联三个供应商激活，任意时刻最多一个未结束激活。
- 号码取得后由后端基于 HeroSMS 返回的激活时间和截止信息计算两分钟取消解锁与二十分钟激活窗口；浏览器时钟不作为权威来源。
- 两分钟后接收者可以二次确认换号；后端以原子状态转换阻止与短信送达并发冲突。
- 只有 HeroSMS 明确确认取消后才创建后继激活；退款确认不作为换号门槛。
- 取消请求不明确时进入对账，确认前不创建后继激活。
- 激活超时结束当前激活，不自动获取新号码；系统查询 HeroSMS 最终状态并进行退款对账，结果不明确时进入供应商对账。
- 激活超时后，接收者需在 24 小时授权期限内再次点击才可使用剩余获取额度。
- 授权撤销或到期后停止所有后继激活；已经发出的 HeroSMS 请求仍需确认和收尾。
- 截止前已发出但截止后才确认成功的号码不得交付，并在允许取消时自动取消。
- 任务状态持久化，应用重启后恢复延迟取消、轮询、完成重试、超时和对账。

### 短信处理

- HeroSMS Webhook 为主接收渠道，`getStatusV2` 轮询为恢复机制。
- Webhook 使用随机秘密路径、配置化来源 IP 白名单、HTTPS、请求体大小限制及激活 ID、服务和地区校验。
- Webhook 在持久化事件后快速返回 200，完成操作异步执行。
- Webhook 和轮询事件按激活 ID、供应商接收时间及负载摘要幂等处理；相同投递重试不能重复转换状态，不同接收时间的短信不能因正文相同被合并。
- 短信送达立即禁止取消、换号和后继激活，不依赖结构化验证码是否存在。
- 有结构化验证码时向仍有访问资格的接收者显示；无结构化验证码时仅管理员可临时查看正文。
- 不使用自定义正则猜测验证码。
- 短信送达后异步调用 `finishActivation`；失败进入完成确认中并重试，但不阻塞验证码展示。
- 接收者页面通过简单状态查询获得更新，不引入 WebSocket；页面关闭不影响后台处理。

### 成本与数据

- 每个成功供应商激活保存 HeroSMS 返回的实际费用和货币。
- 逐笔记录已确认退款；净成本等于累计激活费用减去已确认退款。
- 供应商取消和退款确认分别建模，尚未取得退款确认时不提前减少净成本。
- 完整号码、结构化验证码和短信正文作为敏感交付数据与非敏感历史分离保存。
- 敏感交付数据只在交付、管理员协助或结果对账需要时存在；供应商取消、号码有效窗口结束、激活超时收尾或供应商对账完成后立即删除当前激活的完整号码、验证码和短信正文。
- 非敏感历史长期保留，不提供自动删除、后台删除或批量导出。
- 不配置自动备份；提供选择性 `pg_dump` 手动备份与恢复说明，明确排除敏感交付数据所在存储和 `.env`，常规全库备份不属于受支持流程。

### 管理员界面

- 后台只有登录、首页、激活授权详情和设置四类页面。
- 首页提供创建授权表单、HeroSMS 状态与余额、最近授权及异常状态。
- 详情分别展示授权状态和各供应商激活状态，不压缩成单一状态。
- 详情展示候选地区、获取额度、费用、退款确认和净成本；完整号码、验证码或异常短信正文只在当前有效流程中显示。
- 撤销确认根据当前授权和激活状态明确说明实际动作。
- 不记录管理员读取敏感详情的审计事件；记录会改变状态的管理员命令和供应商生命周期事件。

## Testing Decisions

- 主要测试入口是应用集成测试，通过真实 HTTP 入口和持久后台任务驱动生命周期模块。
- 集成测试使用真实 PostgreSQL 测试实例，验证事务、锁、全局串行、幂等和重启恢复；不使用内存仓储替代关键持久行为。
- 集成测试注入可控时钟和脚本化 HeroSMS adapter，测试只断言模块接口可观察结果，不断言内部函数调用或表结构细节。
- 生命周期测试至少覆盖首次领取、价格排序、无库存回退、三次获取额度、主动换号、激活超时、短信与取消竞争、24 小时绝对期限、撤销、结果不确定、供应商对账、完成重试和敏感数据删除。
- HeroSMS adapter 契约测试使用 OpenAPI 中的成功和错误样本，覆盖 JSON 与兼容文本响应、错误归类、取消冲突、Webhook、状态查询及异常响应。
- 自动测试不调用真实 HeroSMS 账户，不创建真实号码，不依赖供应商实时库存。
- Playwright 只覆盖浏览器负责的关键路径：管理员登录和单会话、设置默认地区、生成并复制链接、移动端领取与绑定、号码和验证码显示、换号确认及 24 小时后 404。
- Playwright 使用桌面与移动视口检查文本不溢出、控件不重叠、倒计时尺寸稳定和接收者页面不泄露内部信息。
- 安全测试覆盖 token 不落日志、链接预览不领取、Cookie 属性、后台路径保护、登录限速、跨浏览器绑定拒绝和过期 token 清理。
- 所有时间测试使用可控时钟，不通过真实等待两分钟、二十分钟或二十四小时完成。
- 测试名称和断言使用 `CONTEXT.md` 中的领域语言。

## Out of Scope

- OpenAI 之外的其他短信服务。
- 接收者注册、登录、个人资料或身份验证表单。
- 公开注册、公开号码选择、公开批量接口或公共号码获取接口。
- 接收者选择国家、地区、运营商或价格。
- 在线付款、待付款状态、售价、利润或对外账单。
- 多管理员、角色权限、管理员邀请、TOTP 或网页密码找回。
- 草稿授权、编辑已有授权候选地区、延长或恢复已结束授权。
- 设备绑定自助恢复或管理员重置设备绑定。
- 自动无限换号、超过三个供应商激活或重复使用已成功获取过的候选地区。
- 将短信送达表述为 OpenAI 验证成功。
- 向接收者展示 HeroSMS、供应商响应、价格、库存、余额、退款确认或内部状态。
- 自动外部通知、邮件、短信、Telegram Bot 或聊天软件集成。
- 自动数据库备份、报表、批量操作、历史删除或敏感数据导出。
- 号码租赁、重复短信、重新发送短信或供应商其他非单次激活产品。
- 多实例横向扩容、微服务、Redis、消息总线或无服务器部署。
- 公开首页、营销页面、多语言切换或原生移动应用。

## Further Notes

- HeroSMS 规则表明前两分钟不能取消，未收到短信的激活在二十分钟后按供应商规则进入退款对账；短信送达后供应商不再确认退款。网站记录供应商事实，不向接收者承诺退款确认。
- OpenAPI 没有为 `getNumberV2` 提供幂等键，因此专用 HeroSMS 账户、全局串行号码获取和不确定结果对账是防止重复激活的必要约束。
- Webhook 文档未定义签名，来源 IP 和秘密路径只能降低伪造风险；激活 ID、服务、地区校验与轮询复核仍然必要。
- OpenAI 的 HeroSMS 服务代码不在现有 OpenAPI 文档中，部署前必须通过 HeroSMS 实际服务列表确认。
- 领域词汇以 `CONTEXT.md` 为准，详细状态规则以领域模型和授权/激活生命周期 ADR 为准。
