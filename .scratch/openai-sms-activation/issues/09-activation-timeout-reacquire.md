# 09 — 处理激活超时并再次获取

**What to build:** 当前激活在二十分钟号码有效窗口内未短信送达时进入激活超时和退款对账。系统不自动获取新号码，由接收者在授权仍有效时决定是否使用剩余获取额度。

**Blocked by:** 08 — 安全换号并执行三地区获取额度

**Status:** resolved

- [x] 激活超时由可控后端时间任务触发并查询 HeroSMS 最终状态
- [x] 退款确认与供应商取消分别记录，未确认退款不减少净成本
- [x] 激活超时不自动创建后继激活
- [x] 授权仍有效且有获取额度时显示获取下一个号码操作
- [x] 接收者再次点击后按剩余候选地区实时报价获取
- [x] 激活超时收尾后删除旧激活的敏感交付数据
- [x] 退款结果不明确时进入供应商对账
- [x] 应用重启后恢复超时与退款对账任务
- [x] 可控时钟测试覆盖二十分钟边界和页面关闭场景

## Comments

- 超时对账以持久状态、领取令牌和单条领取恢复；供应商取消时间与已确认退款记录独立保存。只有 HeroSMS 明确证明未在号码有效窗口内送达时，才向接收者开放“获取下一个号码”。
- 可控时钟集成测试覆盖二十分钟临界点、页面关闭后的重启恢复、最终状态仍等待、窗口后的迟到短信和接收者手动再次获取；Node 集成测试 45/45、类型检查、构建和 Playwright 1/1 通过。
