# 11 — 按生命周期撤销进行中的激活授权

**What to build:** 管理员根据授权状态和当前激活状态撤销进行中的访问。系统立即切断接收者访问，并对可能存在的激活执行延迟取消、供应商对账或只读收尾。

**Blocked by:** 10 — 执行 24 小时绝对授权到期

**Status:** resolved

- [x] 撤销立即切断接收者访问，并统一显示“此链接不可用，请联系发送者”
- [x] 撤销确认显示接收者标识、双状态、当前地区、获取次数和实际后果
- [x] 待领取撤销保持票 03 行为并通过回归测试
- [x] 获取中或结果不明确时先对账，确认号码后尽快供应商取消
- [x] 等待短信未满两分钟时持久安排最早允许时间的供应商取消
- [x] 已允许取消时立即请求取消，且绝不自动换号
- [x] 短信已送达时只终止访问，不尝试供应商取消或期待退款确认
- [x] 撤销收尾后删除不再需要的敏感交付数据
- [x] 已结束或已到期授权不显示撤销操作
- [x] 撤销与短信、取消响应及重启的竞态测试通过

## Comments

- 撤销原子清除接收者会话并保留 token 哈希至 24 小时截止，因此真实撤销链接统一显示不可用，而随机地址和到期链接仍为 404。
- 已领取授权按当前状态显示确认页：等待短信会立即或在两分钟取消窗口到达时取消；获取结果待确认会持续对账；短信送达只终止访问。超时激活继续原有超时与退款对账，不进入撤销取消。
- 撤销取消采用持久任务、最近允许时间定时器与应用重启恢复；供应商 `too-early` 响应会持久延后一分钟重试，避免零延迟重复请求。取消确认会删除完整号码、验证码和短信正文，且绝不启动后继号码获取。
- 真实 PostgreSQL 和可控时钟集成测试覆盖待领取、即时取消、延迟取消、重启、`too-early` 重试、短信已送达、结果不确定对账和取消响应短信竞态。最终 `npm run typecheck` 与 `npm test`（58 项）通过；规格与标准复审无阻塞发现。
