# 08 — 安全换号并执行三地区获取额度

**What to build:** 号码获取满两分钟且未短信送达时，接收者可二次确认换号。供应商取消成功后自动获取后继号码，整条授权最多使用三个候选地区。

**Blocked by:** 05 — 处理号码获取失败与不确定结果；06 — 通过 Webhook 交付结构化验证码

**Status:** resolved

- [x] 两分钟解锁由后端依据 HeroSMS 激活时间判定
- [x] 换号二次确认默认继续等待，确认后原子进入取消确认中
- [x] 仅供应商取消明确成功后创建后继激活，退款确认不阻塞换号
- [x] 取消结果不明确时供应商对账，确认前不创建后继激活
- [x] 短信与取消竞争以 HeroSMS 最终结果为准，任意时刻最多一个未结束激活
- [x] 已使用地区不再使用，无库存地区不消耗获取额度
- [x] 供应商取消后立即删除旧激活的完整号码、验证码和短信正文
- [x] 第三个供应商激活结束后不允许继续号码获取
- [x] 取消成功、冲突、过早取消和异常响应的 adapter 契约测试通过

## Comments

- 接收者在后端确认 HeroSMS 返回的 `cancel_available_at` 后才可进入换号确认页；确认页默认操作为“继续等待”。
- `cancellation_confirming` 是未结束激活状态，并纳入 PostgreSQL 当前激活唯一索引。取消确认、Webhook 和轮询均以条件状态转换处理竞争；短信胜出时不会创建后继号码。
- `cancelled` 激活立即清除完整号码、验证码和短信正文。确认取消后的后继获取由持久 `replacement_pending` 标记驱动，应用启动和后台循环都会恢复。
- HeroSMS adapter 明确区分取消成功、短信冲突、过早取消和异常响应；取消结果不明确时只查询供应商最终状态，不重发取消或提前获取号码。
- 类型检查、构建、完整 Node.js 测试（41/41）和 Playwright（1/1）均通过；数据库测试均自动创建并清理随机隔离数据库。
