# 07 — 恢复短信遗漏与处理无法识别的验证码

**What to build:** 状态轮询能够恢复遗漏短信和应用离线期间事件。没有结构化验证码时，接收者获得统一提示，管理员可在号码有效窗口内查看正文；供应商完成失败可持续恢复。

**Blocked by:** 06 — 通过 Webhook 交付结构化验证码

**Status:** resolved

- [x] 等待短信的激活按受控频率轮询 HeroSMS，Webhook 与轮询结果幂等合并
- [x] 无结构化验证码时显示“短信已收到，暂时无法显示验证码，请联系发送者”
- [x] 管理员只在号码有效窗口内查看异常短信正文
- [x] 后续取得结构化验证码时接收者页面自动更新
- [x] 系统不使用自定义正则猜测验证码
- [x] `finishActivation` 失败进入完成确认中并通过持久任务重试
- [x] 完成结果不明确时保持完成确认并通过供应商状态轮询对账，不重新开放换号
- [x] 应用重启后恢复轮询和完成任务
- [x] 轮询、异常短信和完成错误响应的 adapter 契约测试通过

## Comments

- 使用持久化 `sms_poll_after` 将供应商状态轮询限制为每次激活最多每分钟一次；应用启动和后台任务都会恢复到期轮询。
- Webhook 与轮询统一进入短信事件幂等入口；先收到异常正文、之后取得结构化验证码时只补充验证码，不重复完成转换。
- 接收者异常短信页面每五秒查询状态；管理员详情只在号码有效窗口内展示无法识别验证码的短信正文。
- `completion_confirming` 作为持久完成任务状态，供应商完成失败后保留并在任务循环或应用重启时重试，短信结果始终可交付且不会重新开放换号。
- Node.js 完整测试、类型检查和构建通过；Playwright 因当前环境未配置浏览器测试数据库而跳过。
