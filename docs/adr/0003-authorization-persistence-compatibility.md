# ADR-0003：激活授权持久化兼容模型

- 状态：已接受
- 日期：2026-08-01
- 范围：激活授权持久模型与旧 schema 迁移

## 决策

激活授权表同时容纳旧流程和新链接库存模型。新模型使用 `unclaimed`、`in_progress`、`result_available`、`ended` 四个顶层状态；旧的 `sms_delivered`、`quota_exhausted`、`revoked`、`expired` 状态在迁移和旧写入路径中继续有效，直到后续生命周期切片完成收敛。

创建阶段的 `recipient_identifier`、`normalized_recipient_identifier` 和 `expires_at` 都可为空。待领取链接只保存 token 哈希、末 8 位、创建时间和最近活动时间。`claimed_at`、`number_acquisition_expires_at`、`result_view_until`、`end_prompt_until`、`ended_at`、`ended_reason` 和 `last_activity_at` 分别记录领取、业务期限、结果窗口、结束提示及终局事实，不能用一个创建期限字段混淆这些时间窗口。领取后的 24 小时只限制开始新的号码获取；截止前已经取得的当前供应商激活继续使用其原号码窗口，短信结果查看窗口和额度用尽提示也可以跨过领取截止时间。

token 末 8 位通过生成时保存的 `token_suffix` 管理，使用非空唯一索引约束，不能从 token 哈希反推，也不能作为认证凭据。历史记录无法恢复完整 token 时允许末 8 位为空。旧撤销记录在迁移时清理浏览器绑定，但保留其不可访问状态，不能被重启逻辑恢复为待领取。

候选快照的 `quoted_price` 和 `quoted_stock` 可为空，旧快照仍按原值读取。默认候选配置增加可空 `country_name`；旧的仅地区 ID 配置不伪造名称，只有受控设置流程解析并保存的名称才视为完整配置。

## 迁移要求

初始化 SQL 必须同时支持新建和历史 schema 升级，重复执行不因已存在的列、约束或索引失败。迁移移除旧的接收者标识、创建期限和报价库存必填约束，重建包含新旧状态的状态检查，并建立 token 哈希、末 8 位和候选位置所需的索引。旧状态的历史事实不能被静默改写成新状态，避免破坏现有供应商对账和管理员历史读取。

## 后果

读模型必须接受接收者标识、创建期限和候选报价库存为空。新链接可以在没有接收者、候选位置或供应商调用的情况下持久化；领取和候选配置实例化由后续生命周期切片负责。激活授权与供应商激活仍保持独立生命周期，授权字段的结束事实不能替代供应商激活状态、取消、完成或退款事实。
